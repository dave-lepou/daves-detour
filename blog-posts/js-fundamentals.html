JavaScript (JS) Fundamentals

In this blog, I'm sharing my understanding of JS Fundamentals where I will explore different aspects of JS and how I understand it. I'll talk about JS and its relationship with HTML & CSS, Control Flow, the DOM, Arrays & Objects, and Functions!

JavaScript and its Relationship to HTML and CSS

To understand how a webpage works, imagine building a house:

HTML (The structure): This is the frame, gib, and foundation. It dictates what is on a webpage, like text, buttons, images, etc.

CSS (The appearance): This is the paint, wallpaper, and furnishings. It controls how the structure looks—its colors, fonts, layout, etc.

JavaScript (The functionality and property manager): This is the plumbing, electrical works, etc. It controls how the page behaves when a user interacts with it. Beyond adding behavior, JS acts as the "property manager"—it can step in to repaint a ceiling, knock down a wall, or build an entirely new section on the fly without needing to rewrite the original "blueprint".

Control Flow and Loops

Control flow is simply the order in which a computer executes code. By using conditions (checking if something is true or false), you can control which paths your code takes or repeat certain steps.

Conditionals (if / else): These are decision branches. Think of ordering food: Am I hungry? Yes; Is there food at home? No; Is it past midnight? No; Order Uber Eats!

Loops (for): These repeat an action until a specific condition changes. Example: You keep eating a bag of chips while there are still chips left in the bag. Once the bag is empty (condition becomes false), you stop.

The DOM (Document Object Model)

The DOM is the browser's live/interactive representation of your HTML file. Going back to an earlier analogy about building a home, think of HTML as the blueprint and the DOM as the physical house built that you see IRL (or in this case, on the webpage).

The DOM also creates what we call "nodes", which simply means that the DOM turns everything on the webpage—a heading, a paragraph, buttons, text, etc.—into an individual node so JS can find it and change it. You interact with the DOM using JS in two simple steps:

1. Finding the node: You ask JS to locate a specific element on the page (e.g., document.querySelector('#submit-btn')).

2. Change it!: You change its properties or listen for user actions (e.g., changing the button text to "Chur Bro..." would look like document.querySelector('#submit-btn').innerHTML = 'Chur Bro' or listening for when a user clicks it).

Arrays and Objects - How Data is Accessed

Objects (Access by Name / "Key"): Objects store data in labeled key-value pairs. I like to think of my passport that has keys and values, i.e., the label and the information (e.g., Key: First Name ; Value: Dave / Key: Age; Value: 21 LOL). When you want to find my age, you don't have to guess where in the list it is because you already know the label (key = Age); you would write user.age.

Arrays (Access by Position / Index): Arrays store an ordered list of items, like a queue of people standing in line. You access items based on their exact numerical position starting at index 0 (e.g., colors[0] gets the first item in the list).

Functions: What They Are and Why They Are Useful!

The simplest way to understand what a function is, is to imagine it like a self-contained machine designed to perform a specific task. This machine has two main components: the inputs (parameters), i.e., the raw ingredients you put inside the machine, and the outputs (the return value), i.e., the finished product the machine hands back to you.

Imagine you are craving a smoothie, so you grab a blender to make one. The function is the blender settings (set to smoothie), the parameters are the berries, banana, milk, etc., you throw in, and the return value is the finished smoothie it makes for you! Functions are very useful because of reusability. Instead of having to write twenty lines of code for the same thing, you write the logic once and "call it" whenever you need it.

Here's a wee look at what the code can look like: We first define the machine and ingredients, then process the ingredients to finally get the desired return of a completed, delicious smoothie! 

function makeSmoothie(berry, fruit, liquid) {
  let smoothie = 'A delicious blend of ' + berry + ', ' + fruit + ', and ' + liquid + '!'
  return smoothie
}
